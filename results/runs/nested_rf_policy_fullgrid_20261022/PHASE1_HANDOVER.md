# Phase 1 experiment handover — 22 October 2026

## Scope and baseline

This phase optimized and evaluated the existing six-class PAMAP2 Random Forest and adaptive sensing implementation. It did not change the IEEE report, README, `.gitignore`, or project summary. The historical official-data run `full_fast_1792678712_34ed82` remains intact and is the baseline: eight held-out subjects (101–108), adaptive RF observed-label macro-F1 `0.8574 ± 0.0861`, clean normalized sensing-cost proxy `0.5281`, and moderate wrist-dropout macro-F1 `0.7919`. Its fixed wrist-plus-chest comparator had observed-label macro-F1 `0.9150 ± 0.0482` at cost `0.667`. The separate three-subject run `three_subject_loso_1792678177_dce0aa` gave adaptive `0.7713 ± 0.0238` and all-uniform `0.8446 ± 0.0622`; it is not pooled with the eight-subject result. The legacy tracked quick run remains unverified and excluded.

Subject 109 has no rows in the selected activity IDs 1–6. Subject 103 has only four selected classes. The historical `macro_f1` computes the mean over labels observed in truth or prediction; new results also record `macro_f1_all_classes`, with six fixed labels, so cross-fold comparisons use the same denominator. The two definitions must not be interchanged.

## Search and validation protocol

The new experiment is generated by `python -m scripts.nested_rf_policy_experiment --output results/runs/<new-id> --full-fault-grid`. It checks the official input file sizes and SHA-256 hashes against the historical manifest, then reuses each historical fold's scaler and 50-tree RF checkpoint. For each outer held-out subject, the script trains a 100-tree, depth-20, minimum-leaf-two RF candidate on the same six fitting subjects. The seventh non-test subject serves as inner validation; the eighth is held out entirely from fitting and selection. Both candidates use balanced class weights and seed 42. Window length remains 256 samples with stride 128; no window or feature search was run because changing them would require broader retraining and a new validation protocol.

RF selection maximizes a prespecified validation weighted score: 0.35 clean + 0.25 moderate dropout + 0.20 moderate noise + 0.20 moderate combined-fault fixed-six macro-F1 under all-sensor uniform fusion. The selected model then runs three adaptive policies on the same validation streams: original thresholds (high/low entropy 0.65/0.35, dwell 4, probe 20), conservative switching (0.75/0.45, dwell 8, probe 40), and early reinforcement (0.50/0.25, dwell 8, probe 12). The policy score subtracts 0.10 times clean normalized cost and 0.02 times clean switches per window from the weighted recognition score. The wrist anchor and 0.667 budget remain unchanged. Fault streams are seeded deterministically by subject, scenario, and severity. The selected model and policy are evaluated once per outer test subject across all six configured fault scenarios and three severities. Every compared method receives the same corrupted test arrays within a condition. Validation and test subjects are disjoint within each fold.

The configuration, seeds, input hashes, candidate definitions, objective, and each fold's training/validation/test subject IDs are saved in `protocol.json` and local `subject_XXX_results.json`; compressed `.json.gz` copies are prepared for Git without changing their content. Selected 100-tree checkpoints are saved only for folds that selected them. Clean and moderate-dropout selected-policy window logs include labels, predictions, active masks, actions, and uncertainty. The `completed.json` marker records successful completion of all eight folds; the pilot run `nested_pilot_20261022_subject101` is development evidence only.

## Verified outer-test outcomes

The new experiment has 8,273 test windows across eight LOSO folds. The inner validation selected the 100-tree model in six folds and the historical 50-tree model in two. It retained the original policy in five folds, selected early reinforcement in two, and conservative switching in one.

| Held-out method | Fixed-six clean macro-F1 mean ± subject SD | Clean cost proxy | Observed clean sensor toggles |
|---|---:|---:|---:|
| Historical 50-tree RF and original policy, replayed | 0.8428 ± 0.1158 | 0.5281 | 930 |
| Validation-selected RF with original policy | 0.8418 ± 0.1168 | 0.5278 | 912 |
| Validation-selected RF and policy | 0.8227 ± 0.1194 | 0.5310 | 858 |
| Wrist plus chest, selected RF | 0.8574 ± 0.1116 | 0.6667 | 0 |
| All IMUs uniform fusion, selected RF | 0.8533 ± 0.1108 | 1.0000 | 0 |
| All IMUs reliability-weighted, selected RF | 0.8540 ± 0.1114 | 1.0000 | 0 |

The selected method's 858 toggles equal 0.1037 per test window, compared with 930/8,273 = 0.1124 for the historical model and policy. This modest switching reduction did not compensate for lower recognition. In moderate wrist dropout, fixed-six macro-F1 was 0.7559 for selected adaptive, 0.8217 for all-uniform, and 0.8112 for all-weighted. Under moderate noise it was 0.6471, 0.7630, and 0.7922, respectively; under moderate combined corruption it was 0.6766, 0.7661, and 0.7978. The complete mild/moderate/severe grid is in `fault_grid.csv` and `aggregate.json`.

The optimization did **not** validate an improvement. The original 50-tree model and original policy should remain the recommended configuration for the subsequent documentation phase. The largest clean loss was on subject 105: selected 0.7319 versus replayed historical 0.8474 fixed-six macro-F1. This shows that a single validation subject did not consistently predict transfer to a different person. No final configuration was chosen by maximizing outer-test performance.

The earlier subject-105 one-factor ablation is saved in `../quick_1792677773_f689ab/subject_105_ablations.json`: standard clean F1 0.754 at cost 0.645, while removing the budget raised clean F1 to 0.840 at cost 0.918. That ablation is a separately seeded quick-fold replay and must not be merged with this nested eight-fold table.

## Limits and next phase

Only seed 42 and the prespecified small candidate grid were evaluated. No probability calibration, alternative window lengths, other classifier families, embedded runtime, memory profiling, radio measurements, or hardware energy measurements were added. The normalized cost is an equal-weight sensor activation proxy. Host-side timing includes offline caching and cannot establish embedded latency. Although each outer test subject was excluded from its fold's fitting and selection, subjects had appeared in the previous historical evaluation; this is an exploratory follow-up, not a newly recruited external cohort.

The next phase should decide how to present this negative optimization result alongside the historical manuscript, without replacing the historical report's values or calling the optimized candidate superior. It should review Git tracking of large checkpoints and keep official raw data outside Git. Presentation and institutional similarity report remain separate submission requirements.
